# mfcwProductTransfer 产品转移插件

这是一个适用于 ZJMF 管理系统的产品转移插件包，用于让客户在允许的产品范围内发起产品转出，并由指定客户接收转入。当前版本在原插件基础上优化了后台与前台页面 UI，并新增了“是否需要实名认证”开关。

## 功能概览

- 支持客户把指定产品转移给另一个客户账号。
- 支持后台配置是否启用产品转移功能。
- 支持按产品范围限制可转移的产品。
- 支持配置转出费用和转入费用。
- 支持设置转移有效期，超时未处理的转移会在每日任务中自动关闭。
- 支持设置产品保护期，产品订购后需达到指定天数才允许转移。
- 新增“是否需要实名认证”开关，开启后发起转出和接收转入都需要账号已完成实名认证。
- 优化后台设置页、后台记录列表、前台转出/转入/记录列表页面样式。
- 修复旧版前台转移记录分页链接跳转错误的问题。

## 安装方式

1. 从 Releases 下载 `mfcwProductTransfer-product_divert.zip`。
2. 在安装前备份站点文件和数据库。
3. 将 zip 解压到 ZJMF 站点根目录，并保持目录结构不变。
4. 登录后台，进入插件管理，找到 `ProductDivert` 产品转移插件。
5. 安装并启用插件。
6. 进入插件设置页，配置启用状态、费用、有效期、保护期、可转移产品范围和实名认证要求。

Release 下载地址：

[mfcwProductTransfer-product_divert.zip](https://github.com/jia42520/mfcwProductTransfer/releases/download/v1.0.0/mfcwProductTransfer-product_divert.zip)

## 后台配置说明

| 配置项 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 是否启用产品转移 | 开关 | 关闭 | 关闭后前台不显示转移入口，也不处理待转移提醒 |
| 是否需要实名认证 | 开关 | 关闭 | 开启后，发起转出和接收转入前都会检查当前账号是否通过实名认证 |
| 转移有效期 | 文本/数字 | 7 | 转移发起后允许接收的天数，超过后由每日任务自动关闭 |
| 转出费用 | 文本/金额 | 0 | 发起转出时需要支付的费用，填 0 表示无需支付 |
| 转入费用 | 文本/金额 | 0 | 接收转入时需要支付的费用，填 0 表示无需支付 |
| 保护期 | 文本/数字 | 0 | 产品订购后需要等待多少天才允许转移 |
| 转移产品范围 | 多选 | 空 | 允许客户自助转移的产品 ID 列表 |

## 实名认证开关

本次新增配置项：

```php
realname_required
```

开启后会在以下场景进行检查：

- 客户发起产品转出时。
- 客户进入或提交转入处理时。
- 新版插件前台路由和旧版前台路由都会执行检查。

检查逻辑调用系统已有的 `checkCertify($uid)` 方法。如果当前用户未通过实名认证，系统会阻止产品转移并提示用户先完成实名认证。

## 使用流程

### 发起转出

1. 客户进入产品详情页。
2. 系统判断插件是否启用、产品是否处于 Active 状态、是否满足保护期、产品 ID 是否在允许范围内。
3. 如果开启实名认证，系统检查当前客户是否已实名认证。
4. 客户填写接收方用户 ID 并提交转出。
5. 如果转出费用大于 0，系统生成转出费用账单。
6. 转移记录进入“待接收”状态。

### 接收转入

1. 接收方客户进入产品转移记录页面。
2. 系统检查该客户是否为指定接收方。
3. 如果开启实名认证，系统检查接收方是否已实名认证。
4. 如果转入费用大于 0，系统生成转入费用账单。
5. 账单支付完成后，系统把产品所属用户更新为接收方。
6. 系统关闭或处理该产品相关的未完成账单，并写入操作日志。

### 拒绝或取消

- 转出方可以取消待接收的转移。
- 转入方可以拒绝待接收的转移。
- 每日任务会自动关闭超过有效期仍未接收的转移。

## 转移状态

| 状态值 | 含义 |
| --- | --- |
| `1` | 待接收 |
| `2` | 已完成 |
| `3` | 已关闭 |
| `4` | 已拒绝 |

## 费用与账单规则

- 转出费用和转入费用都可以单独配置。
- 费用为 0 时，系统会自动视为已支付并继续流程。
- 费用大于 0 时，系统会生成 `transfer_fee` 类型账单。
- 接收方支付转入费用后，产品归属才会真正变更。
- 如果转移取消或拒绝，系统会根据账单状态取消或退款相关账单。

## 升级说明

如果你已经安装过旧版产品转移插件：

1. 先备份当前插件目录和数据库。
2. 解压新版文件覆盖到站点根目录。
3. 进入后台插件设置页并保存一次配置。
4. 根据需要开启“是否需要实名认证”。
5. 检查可转移产品范围是否仍然正确。
6. 使用测试账号完整验证一次转出和转入流程。

新增的 `realname_required` 配置项默认关闭，因此覆盖升级后不会改变原有转移流程。只有后台手动开启后，才会要求转出方和转入方完成实名认证。

## 兼容性说明

插件依赖 ZJMF 系统已有能力：

- 插件管理与插件配置表。
- 客户、产品、主机、账单、账单项目等系统表。
- `checkCertify($uid)` 实名认证检查方法。
- `shd_addon_url()` 插件 URL 生成方法。
- `Invoices` 账单逻辑类。
- 每日计划任务钩子。

如果你的系统经过二次开发，请重点确认实名认证函数、账单逻辑类和主题模板路径是否与当前插件一致。

## 验证建议

上线前建议至少测试以下场景：

- 插件关闭时，产品详情页不显示转移入口。
- 插件开启但产品不在允许范围内时，不能发起转移。
- 产品未达到保护期时，不能发起转移。
- 实名认证开关关闭时，未实名用户仍按旧流程处理。
- 实名认证开关开启时，未实名用户不能转出或转入。
- 转出费用为 0 和大于 0 的流程。
- 转入费用为 0 和大于 0 的流程。
- 转出方取消、转入方拒绝、超时自动关闭。
- 旧版前台路由和新版插件前台路由都能正常访问。
